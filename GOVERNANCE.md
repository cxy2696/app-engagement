# Governance

The canonical governance policy lives in [`docs/governance.md`](docs/governance.md).

In short:

- Protocol changes require a design note and a benchmark-schema version bump.
- Model changes require a reproducible benchmark and paired comparisons, not a single metric.
- API changes follow semantic versioning and a deprecation window.
- Data changes require provenance, licence review, hashes, and a data-card update.
- Security reports go through [`SECURITY.md`](SECURITY.md), never a public issue.
